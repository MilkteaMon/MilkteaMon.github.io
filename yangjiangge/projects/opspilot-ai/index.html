Production Scheduling Optimization System

A local production scheduling prototype that compares FCFS, EDD and mixed-integer optimisation, visualises machine schedules, and exports results for Power BI.

Completed

Production scheduling

Source repository is private.

01 / Context

The problem

Allocate jobs to identical parallel machines while accounting for release times and due times. The scheduling model targets total weighted tardiness and makes the tradeoffs between methods visible.

02 / Purpose

The objective

Provide a transparent workflow for comparing baseline and optimised schedules, inspecting job assignments, and preparing coherent data exports for analysis.

03 / Progress

Current status

Completed

The owner confirmed completion of the current personal-project version. The completed scope is a local, single-user scheduling and reporting prototype using synthetic workloads. A public deployment and live evaluation of the optional AI copilot remain outside this completion scope.

04 / Ownership

My contribution

An independent development project maintained under my GitHub account. The detailed contribution breakdown and development dates are awaiting confirmation.

05 / Method

The approach

  • Use a Python/FastAPI backend and React/TypeScript dashboard, as documented in the source repository.
  • Compare deterministic FCFS and EDD baselines with PuLP/CBC mixed-integer optimisation and independently validate resulting schedules.
  • Inspect machine-lane charts, schedule tables, tardiness and utilisation; compare an additional-identical-machine scenario.
  • Export CSV tables, metadata, M queries and DAX definitions for Power BI. An optional AI copilot interfaces with existing functions; live paid AI behaviour has not been evaluated.

06 / Evidence

What is available

  • The supplied GitHub repository documents the scheduling model, application architecture, reporting workflow and limitations. The repository is private.
  • An actual dashboard screenshot from the repository shows a 30-job synthetic demonstration. Its time-limited feasible MILP result is not labelled a proven optimum.
  • This portfolio review inspected repository documentation and the supplied screenshot; it did not independently rerun the application's solver benchmarks or live AI calls.

07 / Looking ahead

Limitations & next steps

  • Document the individual development responsibilities and project dates.
  • Publish a demonstration or source access when it is ready for external review.
  • The current model excludes shifts, setups, maintenance, precedence and heterogeneous machines. Synthetic scheduling results are not company performance improvements or purchasing ROI.
