Production Scheduling Optimization System

A local production scheduling prototype that compares FCFS, EDD and mixed-integer optimisation, visualises machine schedules, and exports results for Power BI.

Completed

Production scheduling

Download project source (ZIP)

01 / Context

The problem

Allocate jobs to identical parallel machines while accounting for release times and due times. The scheduling model targets total weighted tardiness and makes the tradeoffs between methods visible.

02 / Purpose

The objective

Provide a transparent workflow for comparing baseline and optimised schedules, inspecting job assignments, and preparing coherent data exports for analysis.

03 / Progress

Current status

Completed

Completed local prototype for single-user scheduling, scenario comparison and reporting using synthetic workloads.

04 / Ownership

My contribution

Independent development spanning a Python/FastAPI scheduling backend, a React/TypeScript dashboard and a reusable Power BI export workflow.

05 / Method

The approach

  • Generate reproducible synthetic workloads or import job data from CSV, with release times, processing times, due times and priority weights.
  • Compare first-come-first-served (FCFS), earliest-due-date (EDD) and PuLP/CBC mixed-integer scheduling for identical parallel machines.
  • Validate job assignments, release times and machine non-overlap independently, then recompute weighted tardiness, late-job counts, makespan and utilisation.
  • Inspect machine-lane charts and schedule tables, and compare the same workload with one additional identical machine.
  • Export four CSV tables with metadata, Power Query M and DAX definitions for Power BI. An optional copilot provides a natural-language interface to existing scheduling and reporting functions.

06 / Evidence

What is available

  • The downloadable source bundle includes the scheduling engine, independent validator, Web dashboard, tests and Power BI reporting documentation.
  • The dashboard screenshot below shows a 30-job synthetic demonstration and a time-limited feasible MILP result. Feasibility and proven optimality are reported separately.

07 / Looking ahead

Limitations & next steps

  • The current model uses identical machines and excludes shifts, setups, maintenance and precedence. Extensions could introduce these operational constraints.
  • The scheduling engine works independently of the optional AI interface; the solver and validator determine schedule feasibility.
  • Synthetic scheduling results are not company performance improvements or purchasing ROI.
